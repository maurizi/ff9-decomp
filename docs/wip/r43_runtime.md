# R43: runtime questions left by the constants pass over game code

Round R43 named the remaining domain-bearing literal clusters of the game code: world-map story-form cells
(`WM_CELL_*`), areas (`WM_AREA_*`), effect blends and spawn heights, ambient sound sources, flight and camera limits
(ovl_0c), the battle loader steps (ovl_0b), field movie commands, the game-over steps and battle-end results. Names
come from the game's own text where it applies: navi map place names (world text bank 0, read from the disc:
`g_worldNaviPlaces` world positions, entry place + 1 of the bank, docs/r32/3ds-requests-2.md) and the area names of
`g_worldAreaNames` (WM_PACK_AREA_NAMES, read from the disc; identical on all four discs, and R41b's runtime area
numbers match). A map cell is 0x4000 units square: column = x >> 14, row = -z >> 14; the centre of cell (c, r) is
(c * 0x4000 + 0x2000, -(r * 0x4000 + 0x2000)).

The rows below are what the code alone can't settle. Each says what to watch or poke and which state reaches it
(`docs/emulator.md`: "World map anywhere (disc 3)", "World map with any story values", `tools/rt/wm_enter.py`).
Addresses: `g_worldPlayer` 0x800CE3DC (x at +20, z at +28), `g_worldChunkFlags` 0x800D30F8 (one byte per cell,
row * 24 + column), `g_worldFormFlags` 0x800D30C8, story counter 0x8007AEF0, `g_evtGlobalVars.b[n]` 0x8007AEF0 + n.
